# Contributing to WattWise

First off—thanks for thinking about contributing. It means you see potential in this project, and that's flattering, honestly.

---

## How to Help

### Reporting Bugs

Found something broken? Before you report, maybe check if it's already been mentioned. If not:

1. Open an issue on GitHub
2. Describe what you were trying to do
3. What happened vs. what you expected
4. Any error messages (copy/paste them, don't paraphrase)

 Screenshots help. So do steps to reproduce. "It doesn't work" is tough to work with.

---

### Suggesting Features

Ideas are welcome. But before you post that feature request:

- Think about whether it fits the scope. WattWise is meant to be a straightforward energy tracker, not a full-blown smart home platform.
- Consider if it solves a problem most users would have, or if it's a niche edge case
- Explain the use case—why would someone want this? What's the motivation?

---

### Pull Requests

Want to code? Here's how:

1. **Fork** the repository
2. **Create a branch** for your feature or fix:
   ```bash
   git checkout -b feature/cool-new-thing
   # or
   git checkout -b fix/something-broken
   ```
3. **Make your changes** — keep the code style consistent (we use ESLint + Prettier)
4. **Test what you changed** — run the existing tests, add new ones if you're adding functionality
5. **Commit** with a message that describes what you did
6. **Push** to your fork
7. **Open a Pull Request**

I'll review it. Might ask for changes.

---

## Code Style

We use:

- **ESLint** + **Prettier** — 
- **TypeScript** — 
- **Tailwind CSS v4** — for styling
- **Zustand** — for state management

When in doubt, look at the existing code and match the pattern. We're consistent about being inconsistent (meaning: the codebase has established patterns, follow them).

---

## Questions?

If you're not sure about something— whether your idea fits, how to approach a problem, or just want to chat about the project—open an issue and ask. I'd rather have a conversation upfront than see you spend hours on something that won't merge.

---

## The Human Element

This project isn't just code. It's meant to be useful for real people tracking real energy consumption. When you're working on something, ask yourself: "Would a non-developer understand this? Would they find it useful?"

That's the bar. Keep it human.
